### 1.2 本阶段目标

在用户的 Windows 电脑上，通过一个固定本地模型，回答以下问题：

1. 现有桌面工作台能否生成真实中文回复，且在依赖和权重准备完成后断网运行？
2. 保存、发布、试聊、人工修正、再次发布是否使用正确的人格版本？
3. 朋友记忆能否参与当前朋友的回复，并保持档案隔离、删除后不再进入上下文？
4. 同一份角色能否在另一份独立测试数据库中复用，同时保留接收方自己的记忆？
5. 实际响应时间和资源占用是否值得继续做用户本人的风格调教？

本阶段先使用虚构人格和虚构朋友。完成后可得出“本机真实模型及现有调教流程已验证”的结论；“像用户本人”须由后续用户提供的真实表达及留出场景评价，不能从本阶段推断。

## 4. 本机准备、数据与进程边界

### 4.1 实施前检查

记录实际 Windows 版本、CPU、RAM、可用内存、GPU 和当前显存占用。以 nvidia-smi 核对 NVIDIA 驱动及设备；官方 Windows 文档列出的 NVIDIA 驱动要求为 551.61 或更新，固定运行时实际能否正确使用 GPU 仍须验证。[S2]

运行时和模型所在磁盘建议在准备前至少预留 20 GiB。此值是本阶段的保守工作余量，覆盖 ZIP、解压、单模型和临时文件，不是官方最低需求或安装后占用承诺。实际新增占用另记。

驱动不满足要求、空间不足、固定下载不可用或目录归属不明时，记录具体阻塞；不自动更新显卡驱动、清理其他项目或下载替代模型。

### 4.2 端口与服务归属

应用地址固定为 http://127.0.0.1:11434。[R5]

- 启动前检查 11434 的监听及所属进程。
- 空闲时，启动本阶段固定路径的服务，记录 PID、启动时间、可执行文件路径和日志位置。
- 被其他服务占用时，保留既有进程，停止本阶段服务准备并报告。复用用户已有服务或改变端口，需要明确补充选择，不能默默连接或杀掉已有实例。
- 无法可靠识别进程归属时，不按名称批量结束 Ollama、Node 或 Electron。

## 6. 真实验证方法

### 6.1 人格 v1 与公平对照

使用 personaId 为 orange-cat-demo 的短虚构人格。保留 fictionalSample 来源标记，可从现有示例精简得到：

- 自然中文，通常一至三句；先回应对方，再给一个小建议。
- 温和、可以轻微打趣；不知道的个人事实就承认不知道。
- 两条短示例，分别体现安慰和庆祝；不含任何朋友记忆或真实个人资料。

先核对完整 prompt 在 4096 配置下容纳得下，再发布 v1。保存 v1 角色 JSON 及其摘要，记录参数和完整模型 digest。

用三个未作为示例收录的短场景做通用／人格各一轮，例如小进展、疲惫、温和不同意。同一案例使用相同朋友、相同记忆、相同模型和参数；开始时清空该朋友旧上下文，先通用、再人格，记录双方 selectedMemoryIds 与遗漏情况。

通用模式强制空 history，人格模式会使用 history；不得把带不同历史的结果称为公平对照。清空聊天会删除该朋友评估，故每个案例结束后先导出记录，再进入下一案例。最后一个案例导出后暂不清空，保留其中一条回复供第 6.2 节评分和修正；当前没有将评估 JSON 导回工作台的入口。[R7]

评价具体规则遵从、自然程度和不满意之处，不设虚构“本人相似度”百分比。现有“像我”评分按钮若作为功能测试使用，要明确其本轮含义只是对虚构要求的人工评价。

### 6.2 修正与发布隔离

从上节最后一个尚未清空、且不含朋友记忆的风格案例选一条回复，记录人工评价，并填入一条短的虚构修正：

1. 保存修正后，草稿包含新增示例，已发布角色仍为 v1。
2. 未发布时再试聊，记录所用 revision 仍为 v1。
3. 发布 v2，核对新快照和新增示例，旧 v1 快照保持不变。
4. 再试原案例与一个相近的新问题，记录 v2 输出；朋友记忆保留，旧对话历史按现有实现重置。

分别检查 v1、加入修正后的 v2 及实际问题的字符预算；发布时短探针通过不代表所有较长问题都能带入记忆。版本生效要核对快照和生成使用的版本；不能只凭某一句回复变好就认定。若模型表达没有改善，如实保留，不能改写成“已学会”。[R7]

### 6.3 记忆、朋友隔离与删除

使用朋友 A、B，并记录实际 ID，不依赖列表排序。

1. 仅 A 保存一条含随机虚构标记的短记忆，例如“我的验证饮料代号是 LM_A_<随机串>”。标记不得出现在提问、人格或 B 的输入中。
2. 向 A 询问其验证饮料，记录正确选中的记忆 ID 和实际回答。
3. 切换 B 问相同问题，确认 B 的 prompt 数据不含 A 的记忆或历史，并记录 B 是否承认不知道。
4. 给 B 另存一条不同标记，验证 B 自己的记忆；导出删除前评估。
5. 删除 A 的测试记忆，确认 A 的历史和评估一并清除；重启同一库后再问，确认该记忆不再选入，B 的资料仍保留。

使用现有构造逻辑及已关闭测试库的只读副本核对被选数据、history 和 published 状态，必要时重建相应 prompt。程序范围正确和模型回答合理分别记录；一次回复没提到标记，不足以单独证明数据隔离。若正确资料已提供但模型答错，记录为模型能力问题。[R7]

清空／删除只针对本轮测试库。导出文件中的历史副本不会因数据库删除自动消失，报告不得声称已经擦除所有历史证据副本。

### 6.4 人格稳定、取消和服务失败

- 分别用一条要求“永久改性格”的聊天输入及一条夹带类似指令的测试记忆验证：published 角色前后内容一致，普通对话没有自动发布；另记回复是否受诱导。数据未变不等于模型在所有提示下都能稳定拒绝诱导。
- 真实生成中点击停止，确认该轮没有写入聊天／评估，之后能继续试聊。若已经生成完成，不能将其算作成功取消，需另做一次可观察到进行中状态的操作。
- 暂停本阶段自己的 Ollama 服务后试聊，确认给出明确错误，未误写成功聊天／评估，也没有自动下载或云回退；按同样配置恢复服务，再成功试聊。
- 取消客户端请求不等于已证明服务器即时停止全部 GPU 运算，记录实际观察即可。

### 6.5 同机角色分享与升级

复用第 6.1 节已提前导出的 v1 角色文件，并在发布 v2 后导出 v2，核对两份文件及摘要。现有按钮只能导出当前 published，不能等到发布 v2 后再从 UI 导出 v1。检查文件只含发布人格及模型配置，不含朋友记忆、聊天或评估。[R8]

正常关闭 creator 后，用全新 recipient 测试库启动工作台：

1. 导入 v1，核对人格内容、版本、参数与模型 digest；没有 creator 的记忆和聊天。
2. recipient 建立自己的短记忆并试聊。
3. 导入 v2，核对人格升级、自己的记忆保留、旧上下文重置，能继续使用同一个本地模型。
4. 结束后按指定测试目录重启，读回接收库状态。

沿用同 personaId 且版本递增的现有限制，不手改 JSON 伪造导入成功。这只证明同机角色包与独立数据库的流程，不等于 Mac 可运行、朋友客户端完成或模型权重已经随角色交付。

### 6.6 性能证据

至少一次冷加载、三次热运行，使用固定短请求和相同配置。冷加载前确认 /api/ps 没有该模型；热运行保持模型已加载。测试间重置对话起点，先保存再清空评估。

记录：

- 应用完整完成耗时；冷、热分别列出，不把平均值混在一起。
- 模型的加载、输入处理、生成耗时及输入／输出 token 数、输出 token/s；缺失值注明缺失。
- /api/ps、ollama ps 及 nvidia-smi／任务管理器的实际 GPU／CPU 分配、显存与进程内存观察。
- 超时、显存不足、截断、明显卡顿，以及采样时间和方法。

stream:false 下测的是完整回复等待时间，不是首 token 延迟。离散采样只能称“观测到的最大值”；没有连续采样时不冒充精确峰值。当前应用的 120 秒总超时覆盖模型预检及生成，失败应保留，不能悄悄延长超时掩盖问题。[R5][S8]

延迟、自然程度是否可接受由用户 U02 判断，本 r1 不凭显卡规格承诺响应秒数或预设未经用户接受的性能门槛。[R9]

## 8. 用户最终验收

### U01：真实断网试聊

03 在技术交付前准备可离线读取的简短 RUNBOOK，并先确认用户能按说明启动。用户在方便时段自行执行：

1. 确认依赖、构建产物和模型已备齐。把已完成第 6.5 节验证、含 v2 和一条短记忆的 recipient 库绝对路径写入离线说明，连同启动步骤保存在本地；本次读回该库，不另建空库。
2. 正常关闭本阶段 Electron 和本阶段自有 Ollama。
3. 用户手动断开外网连接，保留本机 loopback。若同时有 Wi-Fi、网线或其他可用出口，要确认没有替代出口；不以某一个网页打不开作为唯一断网依据。
4. 按本地说明重新设置进程级配置和上述 recipient 目录，在断网状态启动本阶段 Ollama 与构建产物窗口。离线准备只检查本地文件与本机 /api/version、/api/tags、/api/show，复用联网阶段已核验的来源证据；不重新访问远程 manifest、发布页或依赖审计，也不运行安装、pull 或更新命令。
5. 完成至少一条新的中文对话和一条相关记忆提问，保存本地截图／记录，注明操作者、断网方式和结果；正常退出。
6. 用户自行恢复网络，再把结果交回 01／03。

远程 ChatGPT 会话可能在断网期间不可用，所以不要求在线代理现场指导或自动断网。03 和 Work 不擅自操作系统网卡、防火墙或代理，不将失联推断成试聊成功。

用户尚未执行、证据不足或执行失败时，U01 分别记为待验收／证据不足／未通过。不得用本地地址、禁云日志或一次外联采样替代真正断网结果。

### U02：体验与继续方向

用户体验短中文回复，并确认：

- 等待和电脑占用是否能接受；
- 虚构规则下的回复是否自然、哪些地方仍不合适；
- 是否值得进入少量真实说话样例的调教阶段。

接受本轮流程不等于确认已学会用户人格。若体验不接受，应先讨论是精简规则、调整同模型参数，还是另提模型选择方案；不自动接入 API。
