## 2. 本阶段要交付的结果

用户能够按照一份准确的 Windows 操作说明，在指定运行环境中打开真实的 Electron 工作台，修改并保存虚构人格草稿，维护独立朋友档案与手动记忆，正常退出并重新打开后读取相同数据。

完成本阶段，能够证明的是：已有 M0 工作台在这台 Windows 电脑上的运行、IPC、本地数据库和基础界面流程达到下述验收标准。

真实模型对话、像用户的程度、模型检索记忆效果、断网聊天、macOS 体验以及最终桌宠形象和行为，仍是后续阶段的独立验收目标。

## 3. 已知事实与设计依据

1. 项目声明宿主 Node 范围为 >=24 <27，当前归档记录的 Windows PATH 中为 Node 22.15.0，且无已安装依赖。历史 41 项测试、类型检查和构建来自 Linux / Node 24，不能作为本阶段 Windows 结果。[S1][S2]
2. 本阶段拟固定 Node.js 24.22.3 Windows x64 及随附 npm 11.19.1。选择 Node 24 是为了与历史基线保持主版本一致，并非认定项目范围内的 Node 26 不可用。固定版本下载及摘要可从官方发行页核对；当前方案阶段没有下载或执行该运行时。[S6]
3. 项目锁定 Electron 45.4.1。Electron 官方说明从 42 起调整二进制准备行为；npm 依赖安装成功不能单独证明 Electron 二进制已经就绪。本项目开发脚本直接导入 electron 并启动其路径，必须单列二进制准备检查。[S2][S3][S8]
4. 草稿保存、朋友新增、手动记忆保存/删除不调用模型；发布人格要先列出并校验本地模型，试聊还要求存在已发布版本。因此发布、正常角色导出和真实聊天不列入本阶段必过项目。[S5]
5. ORANGE_CAT_DATA_DIR 已支持指定应用 SQLite 数据库目录，无需为数据库隔离新增功能。它没有改变整个 Electron userData/profile，不能宣称所有 Electron 用户数据均已隔离。[S4]
6. 开发端口 127.0.0.1:5173 同时受 Vite strictPort、启动脚本、主进程来源检查和 CSP 约束。端口冲突应先报告和处理本次进程，不能仅改一个端口配置或终止无关进程。[S3][S4]

## 5. 实施设计

### 5.1 Node 环境

拟使用 Node.js 24.22.3 Windows x64 官方 ZIP，随附 npm 11.19.1。[S6]

- 固定下载地址：https://nodejs.org/dist/v24.22.3/node-v24.22.3-win-x64.zip
- 预期文件名：node-v24.22.3-win-x64.zip
- 官方 SHA-256：e612af99f626ab415ea225af6bce5c971feb448cb5cae250bb1c3fa50c5f7d9f
- 建议独立目录：D:\tools\IdeaTool\runtimes\node-v24.22.3-win-x64

批准后优先复用来源可核验的同一版本；否则下载固定文件并在本机计算摘要，匹配后解压。目录已有内容时先检查，不能覆盖不明文件。

仅调整本次 PowerShell 及子进程的 PATH，或使用明确的可执行文件路径。记录 node.exe、npm.cmd 的实际路径及版本。保留原 Node 22 和永久 PATH；不安装全局版本管理器、不升级全局 npm，不为执行 npm.ps1 改系统执行策略。

其他 Node 补丁或主版本不自动替代本次固定基线。若固定版本不可获得或发现新的适用性问题，先形成修订依据。

### 5.2 依赖与 Electron

在确认的项目工作区执行现有锁文件对应的 npm.cmd ci --include=dev。使用固定 Node 所带 npm，保留 package.json 与 package-lock.json。[S7]

npm ci 会处理安装目录而不是只读检查。操作前确认 node_modules 是否存在及其归属；若有用户手工改动或来源不明内容，保留并改用明确的隔离工作区或报告具体问题。不要自动重生成锁文件、改用 npm install 或添加改变依赖解析的选项来掩盖失败。

本方案批准后，允许下载锁文件指定的公开依赖，并执行已核对、为这些锁定依赖所必需的安装步骤。遵守现有脚本执行政策；需要额外权限或未列明服务时报告原因，不更改全局 npm 配置或使用宽泛绕过开关。

随后检查本地 electron 包版本、二进制路径与可执行性。必要时调用已安装的本项目 electron 包所提供的 install-electron 工具，准备锁定的 45.4.1 Windows x64 二进制。使用本项目已安装的工具，不以可隐式临时安装其他版本的命令替代。[S8]

记录实际 Electron 版本，并区分宿主 Node 与 Electron 内嵌 Node。外部 Node 的测试结果不能替代 Electron 内 SQLite 和真实窗口验证。

### 5.3 数据与进程隔离

- 为每次完整验收建立独立目录，例如：
  D:\tools\IdeaTool\project\desktop_pet\test-results\M0-WIN-VERIFY\r1\<本次运行编号>\data
- 在启动子进程前，以进程级环境设置 ORANGE_CAT_DATA_DIR。通过界面的“本地数据位置”确认实际 SQLite 路径确实在该目录。
- 使用全新测试数据库，且只使用虚构验收素材。不要修改用户默认的 orange-cat-lab.sqlite。
- 同一次持久化验收必须复用同一个测试目录；重新从空状态完整验收时另建运行编号，不覆盖旧证据。
- 记录自己启动的 PID 和命令。正常关闭窗口并确认本次进程、开发服务和端口释放；不得按进程名称批量终止其他 Node/Electron。
- 环境设置仅在本次会话有效，结束后恢复；不修改系统网络或停止用户已有的模型服务。
- 数据隔离只承诺应用 SQLite 目录隔离；不删除或声称替换整个 Electron profile。

### 5.4 两条启动路径

1. 开发路径：预检 5173 后执行 npm.cmd run dev，验证真实 Electron 窗口和 IPC。
2. 构建产物路径：生产构建成功、开发进程已结束后，使用本项目锁定的 Electron 从项目根目录启动。确认 ORANGE_CAT_DEV_URL 不影响该次启动，使用 pet://app/index.html 及 dist 中资源。

第二条路径用于验证本地构建产物可运行，不等于已生成或验证安装包。单独在浏览器打开 Vite 页面只能作为辅助观察，不能替代真实 Electron 验收。

### 5.5 修复边界

默认先按照现有源码验证。批准 r1 后，可以连续处理直接阻塞下表的 Windows 路径、启动或进程收尾问题，并对具体问题记录修复和必要回归。

涉及以下变化时，先修订 PLAN 并取得相应决定：

- 修改 Node engines、主要依赖版本、依赖声明或锁文件。
- 改变数据库结构、人格发布/记忆业务含义、模型接入或网络目的地。
- 放宽 CSP、来源检查、IPC 边界或现有安全设置。
- 新增安装器、自动下载模型、后台常驻服务或大规模重构。
- 降低本方案验收条件。

不通过删除失败测试、放宽断言或伪造模型/GUI结果获取通过。补充测试仅针对具体缺陷与必要回归，不为文档和可逆环境操作添加镜像式测试。

## 7. 验收标准

所有“通过”都要注明执行环境、实际提交与证据。以下 A01–A10 是本阶段的验收条件；没有证据的项目应记为未验证，不能因其他项目通过而自动通过。

| 编号 | 操作或检查 | 通过标准 |
| --- | --- | --- |
| A01 | 环境与锁定版本 | 确认 Windows x64；宿主 Node 24.22.3、npm 11.19.1和真实路径；Electron 45.4.1二进制可执行；记录其内嵌运行时；原 Node/PATH 的永久设置未变 |
| A02 | 现有自动检查 | Windows 上类型检查、现有测试、生产构建成功；保留实际测试数/退出码。原基线41项不得无故减少；新增项如实记录；模拟测试不作为真实推理证据 |
| A03 | 两条真实 GUI 路径 | 开发启动和构建产物启动均出现真实 Electron 窗口；页面可切换，IPC可用，展示正确数据库位置；不存在把浏览器预览当桌面成功的情况 |
| A04 | 草稿保存 | 在虚构样例中修改名称/一条规则并保存，状态正确，页面切换后可读取。不能把验收样例描述成已学习用户真实人格 |
| A05 | 朋友档案 | 新增虚构朋友 WIN_VERIFY_C，可选择，重启后仍存在；默认朋友 A/B 不重复创建 |
| A06 | 记忆分离 | 分别在朋友 A、B 保存 WIN_VERIFY_A 与 WIN_VERIFY_B，切换时只显示该朋友的内容；按朋友名称/ID核对，不依赖列表排序 |
| A07 | 删除与重启 | 删除 A 的测试记忆并确认，B 的记忆保留；正常退出并重开同一数据目录后，已保存草稿、C档案、B记忆、A删除结果均保留 |
| A08 | 无模型的正常限制 | 全新测试库保持尚未发布；未选择模型时不能发布，试聊/正常角色导出受限制；草稿和记忆页面仍能使用。不注入伪造的已发布包来通过 |
| A09 | 收尾和数据边界 | 本次进程正常结束；开发服务释放占用端口。应用数据库写入指定测试目录，未修改默认个人数据库；无真实私人数据和生成目录入库 |

补充边界：

- 当前选中的朋友和标签在基线中不是持久化状态，不要求重启后恢复相同选中项。
- 删除测试记忆不等于已经验证“含真实聊天记录时清除历史”的完整效果。

## 10. 风险、备份和恢复

| 风险 | 处理方式 |
| --- | --- |
| 命令仍使用Node22 | 核对可执行文件路径与版本，再运行后续步骤；只切换本次会话 |
| 下载失败、锁文件不一致或安装脚本受限 | 记录实际错误，不以升级依赖、重写锁文件或关闭政策掩盖；在范围内诊断，否则提出修订 |
| Electron二进制缺失或内嵌SQLite不兼容 | 单独核对二进制；以真实窗口/SQLite读写验证；必要时停止并提交明确修复方案 |
| 5173被其他程序占用 | 不终止无关进程，不只改Vite单点配置；说明占用，协调可用时间或修订完整配置方案 |
| 验收数据污染原数据 | 从启动前设置并确认测试数据库路径；仅使用虚构数据，不触碰默认数据库 |
| 数据库仍被占用 | 先正常退出本次应用和服务；保留数据目录，复核时只用已关闭的测试库 |
| 小修复扩大为重构 | 以第5.5节和A01–A10为边界；超出时修订PLAN |

恢复方式：

1. 正常结束本次进程，关闭或恢复本次 PowerShell 环境，其他项目继续使用原运行环境。
