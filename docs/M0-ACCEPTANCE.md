# M0 验收与下一步

## 已通过的产品约束

1. Windows 开发，独立应用覆盖 Windows/macOS。
2. 离线优先、固定发布原型、朋友独立记忆，暂不接入收费云 AI。
3. 形象为用户稍后提供参考的橘猫；先用文字占位，不能把占位当成最终猫形象。
4. 规则/样例/修正先验证，再决定是否有必要微调权重。
5. 任何未来需要 API credit 的环节，先说明用途、预估用量、来源与停止条件。

## 当前交付边界

M0 是**创作者的离线语言验证工作台**。已实现手动调教、版本发布、朋友隔离、受限本地连接和评估记录。当前没有自动记忆提取、LoRA、语音、正式素材、桌面悬浮、开机自启、自动更新或内置模型运行时。友人最终使用版与角色原型可复用当前核心，但其安装体验尚未完成。

## 目标机验证顺序

| 检查     | 方法                                  | 记录                                   |
| -------- | ------------------------------------- | -------------------------------------- |
| 启动     | 在 Windows 按 README 启动独立窗口     | 是否报错、窗口是否可操作               |
| 本地模式 | Ollama 禁用云，工作台只列本地权重模型 | 日志与模型名称/指纹                    |
| 普通试聊 | 同一模型、短回复、4K/8K 起始上下文    | 首次/热启动总耗时、token/s             |
| 资源     | 聊天时查看任务管理器和 `ollama ps`    | RAM/显存、CPU/GPU分配、后台占用        |
| 真实风格 | 用用户提供的首批真实表达取代虚构样例  | 适合与不适合的回复及修正               |
| 新场景   | 用未收录为示例的问题测试              | 语气、反应、自然程度、事实边界         |
| 版本隔离 | 改草稿 → 未发布试聊 → 发布后试聊      | 未发布不生效，新版生效                 |
| 朋友隔离 | A保存偏好，B提问；重复切换并重启      | 不交叉注入资料                         |
| 删除     | 删除A记忆，重启后再次提问             | 记录和上下文已清理，不能靠残留继续引用 |
| 断网     | 准备好全部依赖与权重后断网试聊        | 核心试聊是否继续，不转向云端           |
| Mac      | 补芯片/内存后重复运行与安装检查       | 单独记录，不用Windows结果代替          |

具体速度与风格是否合格由用户实际体验决定；目前不捏造响应时间目标或“相似度”。先挑少量真实场景暴露问题，再扩大样本，不要求一开始导出全部聊天记录。

## 调教材料第一批

建议提供约 20–40 个“对方说什么 → 我会怎么说”的短例子，覆盖：日常打招呼、开心、沮丧、拒绝、不同意见、打趣、关心、结束聊天。可以先给 5–10 条开始试用，数量只是准备工作量的建议，不是质量保证。

不要把所有训练样例同时塞入一个有限上下文。M0 先用精简示例与规则验证；后续再实现本地样例检索、分场景注入和可审核的自动提议。

## 后续迭代

1. **M0 真机语言验收**：找出本地候选模型的能力与资源边界，建立真实表达样例。
2. **M1 桌面宠物壳**：透明窗口、拖动、托盘、置顶/穿透、基本行为状态机和资源回收。
3. **M2 橘猫形象与行为**：用户提供参考后制作角色、动作资源，连接本地行为状态和对话事件。
4. **M3 朋友版交付**：仅使用已发布原型、内置对应平台推理器、模型资源导入、可选首次下载、数据迁移和实际安装验收。
5. **按证据决定增强**：先改善规则/检索/本地模型；只有离线评估无法满足目标时，再提出有预算的云端辅助或训练方案。

当前不会自动发起 CI 服务、注册开发者账号、上传角色到公开服务或购买证书。
