# 橘猫桌宠 · M0 离线人格验证工作台

这是独立桌宠项目的第一阶段工程。它先验证“本机模型能否按照你确认的规则、说话样例与朋友记忆进行中文对话”，然后再进入正式橘猫素材、桌面透明悬浮窗和朋友安装包阶段。

**当前交付：源码 + 锁定依赖 + 本地验证界面 + 测试 + 打包配置。不是已验收的 Windows/macOS 安装包。**

## 费用与联网边界

- 本版本没有云 AI 调用路径，没有 API Key 输入框，也没有自动回退云模型。
- 文本生成只访问 `http://127.0.0.1:11434` 的 Ollama；`API` 在这里是本机进程接口，不是 OpenAI 收费接口。
- 调教方式是人工规则、表达样例、人工纠正和本地记忆检索；没有微调模型权重，没有 LoRA。
- 安装 Node、npm 依赖、Electron、Ollama 和首次下载模型需要网络与磁盘空间。其下载本身不消耗 OpenAI API credit；网络流量、电脑耗电另计。
- Ollama 自身也支持云模型。因此必须按下方流程在启动 Ollama 前关闭其云功能。工作台同时拒绝云模型名称、远程模型元数据、非本地 GGUF、模型指纹变化与 HTTP 重定向。
- 本轮没有替你下载模型、安装软件到你的电脑、启动训练、购买证书或调用付费 AI 服务。

Ollama 的本地模式和关闭云功能说明：[官方 Local FAQ](https://docs.ollama.com/faq)。

## 1. Windows 上运行

### 准备开发环境

1. 安装 [Node.js](https://nodejs.org/en/download) **24.x**。
2. 安装 [Ollama Windows 版](https://ollama.com/download/windows)。
3. 将工程解压到普通工作目录，例如 `D:\projects\orange-cat-desktop`。

当前已知目标：Windows 11 x64、i7-11800H、16 GB 内存、RTX 3070 Laptop 8 GB。它适合作为 4B 量化模型的第一轮测试设备，但速度、显存、温度与实际模仿效果还没有在这台电脑上测量。

### 启动仅本机的 Ollama

如果 Ollama 已在系统托盘运行，先从其托盘菜单退出。在新的 PowerShell 窗口中运行：

```powershell
$env:OLLAMA_NO_CLOUD = "1"
$env:OLLAMA_HOST = "127.0.0.1:11434"
ollama serve
```

保留这个窗口。确认启动日志出现 `Ollama cloud disabled: true`。这些环境变量只影响此终端及其子进程；日后从开始菜单启动 Ollama 时，不会自动继承本次 PowerShell 设置。以后测试时重复此启动方式，或按官方文档保存同等本地配置。

如果显示端口已占用，先确认是否仍有你自己启动的 Ollama 实例；停止那个实例后再启动。不要把主机地址改成公网服务或 `0.0.0.0`。

### 准备第一轮候选模型（仅首次需要）

在**另一个** PowerShell 窗口中：

```powershell
ollama pull qwen3:4b
```

核对时，Ollama 的 [qwen3:4b 模型页](https://ollama.com/library/qwen3:4b) 显示约 2.5 GB、Q4_K_M 量化。这只是模型资源大小，不是运行时总内存/显存。它是可替换的验证候选，不宣称是最新或最好的中文陪伴模型。

若已经安装了合适的本地 GGUF 模型，可以先用已有模型，不必重复下载。工作台不会自动执行 `pull`。

### 启动工作台

在工程根目录运行：

```powershell
npm ci
npm run dev
```

`npm ci` 会按 `package-lock.json` 安装锁定版本，开发环境还会下载 Electron。若 PowerShell 提示不允许执行 `npm.ps1`，直接使用随 Node 安装的 `npm.cmd ci` 和 `npm.cmd run dev`，无需修改系统脚本执行策略。

界面会打开独立 Electron 窗口。开发阶段修改 Vue 界面会热更新；修改主进程或预加载代码后需重新运行 `npm run dev`。

`npm run dev:ui` 仅打开可检查的浏览器界面，明确显示“界面预览”；它不保存数据，也不模拟 AI 回答。实际功能应通过 Electron 启动。

## 2. 第一次完整试用

1. 打开“调教与发布”，阅读初始规则和两个例子。它们明确标为**虚构开发样例**，还不是你的真实习惯。
2. 点击“检测已安装的本地模型”，选择本机模型。默认运行参数为 8K 上下文、384 输出 tokens、温度 0.7 和固定随机种子 42，均可调整。
3. 发布第一个**测试版本**。发布会固定原型、模型名称、模型指纹和主要参数；不调用模型生成，也不进行训练。
4. 在“试聊与评估”选一个场景，点击“按发布性格回复”。首次生成包含模型加载时间，后续耗时应单独比较。
5. 评价“像我 / 还需要调教”。点“我会这样说…”后输入自己的回复，会加入**草稿**；再次检查、保存并发布才影响后续对话。
6. 在“记忆与交付”只给朋友 A 保存一条测试偏好，再切换朋友 B 对话，确认 B 没有拿到 A 的资料。
7. 模型已经下载后断开网络，再完成一次试聊。应用不会转向云服务。

做通用对照时，先清空该朋友的试聊，保留同一组记忆。对同一个问题分别运行人格回复和通用单轮对照；通用对照不写入人格的会话历史。这里不计算虚构的“人格复制百分比”，由你评价自然程度和一致性。

内置 8 个场景还覆盖：小进展、疲惫、不同意见、记忆使用、未知经历、要求覆盖性格、记忆中的越权指令、其他朋友资料。部分场景需要先手工添加界面提示的测试记忆。

### 重要的实现边界

- 当前长期记忆**只由手动保存**产生，没有自动总结或自动学习；下一阶段再评估是否增加可审核的记忆提议。
- 发布新版本时保留朋友记忆，清空短期会话上下文，避免旧回复把新性格拉回旧版本。评估记录保留版本号供比较。
- 删除一条朋友记忆时会清空该朋友的全部试聊记录和上下文，避免旧回复继续引用它。你主动加入角色草稿的样例是另一份发布数据，需自己在编辑器删除并发布新版本。
- 本轮提示预算以字符粗略限制，**字符不是 token**。固定原型与当前输入太长会明确报错；不会静默丢弃角色规则。较旧历史或低优先记忆被省略时，界面会标示。
- 保存与结构校验能防止程序日常误改原型，不能保证所有模型输出都不偏离，也不能阻止电脑所有者修改程序或角色文件。
- 在创作者工作台中，角色导出是 JSON，只包含你确认发布的规则、样例、版本和模型配置。它不包含朋友记忆、对话、模型权重或尚未制作的橘猫素材。
- 此 M0 工作台是创作者的调教工具，含编辑能力。后续朋友版会采用仅载入发布角色的使用界面；不要把 M0 当成最终朋友版。

## 3. Mac 的当前状态

已知朋友设备为 MacBook Pro 13 英寸、macOS 26.5.2。截图没有给出芯片和内存，不能据此确定 arm64/x64 或模型性能。

Mac 开发验证也可以使用 Node 24 + Ollama + 此工程。若手动启动 Ollama，在退出其菜单栏实例后用独立终端：

```bash
OLLAMA_NO_CLOUD=1 OLLAMA_HOST=127.0.0.1:11434 ollama serve
```

另开终端准备模型和运行工程即可。此步骤是开发验证；未来朋友版不要求对方安装 Node 或配置开发环境。

## 4. 打包和签名

完整说明见 [docs/DISTRIBUTION.md](docs/DISTRIBUTION.md)。当前 `package.json` 为**未购买发布者证书的内测配置**：

```powershell
# 在 Windows 构建 Windows x64 测试安装包/压缩包
npm run package:win
```

```bash
# 在 macOS 构建；按目标 Mac 芯片选择一种
npm run package:mac:arm64
npm run package:mac:x64
```

输出目录为 `release/`。这些命令可能需要下载平台打包工具。当前没有执行这三个目标平台打包命令，没有产出签名安装器，也没有验证目标电脑的首次安装。

Mac 配置使用临时代码签名 `identity: "-"`，不是付费 Developer ID，也没有 Apple 公证。Windows 配置只禁用发布者签名，保留应用资源元数据编辑。正式分发前要换成对应的签名、公证和发布校验配置。

源代码包中的 `npm ci` 是开发者步骤。最终交付给朋友的目标仍然是：安装程序 + 对应架构的推理运行时 + 可单独复用的模型资源 + 已发布角色资源；朋友无需 ChatGPT 套餐、OpenAI API Key 或开发环境即可完成本地核心使用。

## 5. 工程结构与扩展方式

| 位置                    | 职责                                                                      |
| ----------------------- | ------------------------------------------------------------------------- |
| `packages/persona-core` | 纯函数：规则、样例、版本、作用域隔离、提示与人工评估场景；不依赖 Electron |
| `packages/local-model`  | 固定本地 Ollama 连接、云模型拦截、指纹核对、请求预算、取消及指标          |
| `src/main/service.ts`   | 用例编排：发布、试聊、人工修正、朋友记忆、导入导出                        |
| `src/main/store.ts`     | SQLite 版本化文档仓库及事务；较新数据库版本拒绝写入                       |
| `src/main/bundle.ts`    | 可发布角色包的显式字段校验；拒绝混入朋友数据                              |
| `src/main/index.ts`     | 桌面窗口、限定 IPC、原生文件对话框及本地资源协议                          |
| `src/preload`           | 渲染界面可调用的窄接口，不暴露任意文件和 IPC 操作                         |
| `src/renderer`          | Vue 界面；不直接持有数据库或模型权限                                      |
| `test`                  | 服务与持久化集成测试，使用明确的假模型客户端                              |

SQLite 当前将不同集合中的版本化 JSON 文档分别保存，适合 M0 的少量原型和测试记录。不是为大量用户设计的云数据库。模型连接、人格逻辑与界面已经分离，后续可以增加 llama.cpp 适配器、嵌入式模型运行时、专用朋友界面、桌面行为状态机和素材包，而不用重写人格核心。

数据库保存在 Electron 用户数据目录，具体路径在“记忆与交付”可查看。数据为本机明文 SQLite；备份时退出应用，再复制该数据目录。角色导出不会把此数据库打包给朋友。

代码是该私有项目的起点，本工程没有替你选择公开开源许可。第三方依赖和日后模型/素材分别遵循各自许可；正式发布前保留相应版权与许可证。
